# Data

The meshes come from the ShapeNetCore.v1 subset that was preprocessed for the MeshSDF checkout in
`$WORK/MeshSDF`. This directory holds the tools that expose that data to this repo, build the mesh sets the
research scripts read, and regenerate everything from the raw download. Paths below use the variables of
`kairos/config.sh` (`IA3D_DATA` is `$WORK/irr/ImpliAnim3D-stage/data` by default); run
`source kairos/config.sh` to have them in your shell. Commands are run from the repo root.

## What the data is

- **Source:** ShapeNetCore.v1 from HuggingFace `ShapeNet/ShapeNetCore-archive` (gated, 32 GB zip).
- **Subset:** the first 200 model ids (sorted) of each of the 57 synsets, listed in
  `splits/shapenet_v1_200_per_category.json` as `{"<synset>": {"samples": [ids]}}`. 35 synsets have 200
  models, the other 22 have all of theirs (56 to 186): 9,365 ids. `splits/synset_names.json` maps synset
  ids to category names.
- **Preprocessed:** 9,363 of them. Two ShapeNet OBJs contain no geometry and cannot be processed
  (`03624134/67ada28ebc79cc75a056f196c127ed77`, `04074963/b65b590a565fa2547e1c85c5c15da7fb`).

Per model, under `<synset>/`:

| File | Content |
|---|---|
| `meshes/<id>.obj` | Watertight, outward-oriented shell of the shape, at most 100,000 faces, `v` and `f` lines only (about 3.7 MB). This is what the SDF datasets of this repo load. |
| `samples/<id>.npz` | Arrays `pos` and `neg`, float32, shape `(N, 4)` with columns x, y, z, signed distance. `pos` holds the samples outside the shell (distance >= 0), `neg` the ones inside; together 500,000 rows (308,172 + 191,828 in the file that was opened). The research scripts do not read these yet: they sample the mesh online with `pysdf`. |
| `renders/<id>/` | 16 views per model for MeshSDF's single-view reconstruction. Present in the linked data, not used by this project, and not regenerated by the tools here. |

How a mesh is made (`regen/preprocess_sdf.py`, the recipe of the MeshSDF setup):

1. All parts of the raw OBJ are concatenated and normalised DeepSDF-style: bounding-box centre at the
   origin, furthest vertex at radius 1/1.03.
2. Raw ShapeNet meshes are open and inconsistently oriented, so the surface is replaced by a closed shell,
   as DISN did: unsigned distance on a 256^3 lattice over [-1.05, 1.05]^3, flood fill of the free space from
   the border, marching cubes of the 1.5-voxel offset, decimation to 100,000 faces.
3. The shell therefore sits about 0.012 outside the original surface and reaches radius 0.98 (0.979 to
   0.983 over the 60 meshes of the default set). Everything stays inside the unit ball.
4. SDF samples are taken against that shell: 95% near the surface (surface points perturbed with variance
   0.0025 and 0.00025), 5% uniform in [-1, 1]^3, sign from the winding number.

## Where it lives

```
$IA3D_DATA/
  shapenet/<synset>/{meshes,samples,renders}   one symlink per synset -> $WORK/MeshSDF/data/<synset>
  raw/ShapeNetCore.v1                          symlink -> $WORK/datasets/ShapeNetCore.v1 (zip + extracted_200)
  sets/<name>/                                 mesh sets in the layout the research scripts read
```

Nothing is copied, so **the links break if `$WORK/MeshSDF/data` is removed or moved.** To own a real copy
instead (about 106 GB for meshes and samples; add `--exclude=samples` for the meshes alone, about 35 GB):

```bash
source kairos/config.sh
rsync -a --exclude=renders "$WORK"/MeshSDF/data/0* "$IA3D_DATA/shapenet.real/" \
  && mv "$IA3D_DATA/shapenet" "$IA3D_DATA/shapenet.links" && mv "$IA3D_DATA/shapenet.real" "$IA3D_DATA/shapenet"
```

The sets point into `$IA3D_DATA/shapenet`, so they keep working after that swap.

## Mesh sets for the research scripts

`train_GT2.py`, `train_weights.py` and `test.py` address meshes as `<root>/<i>.obj` and `<root>_90/<i>.obj`
with a 1-based index (`train_GT2.py` uses 1..25, `test.py` uses 40 as the unseen mesh).
`make_legacy_set.py` builds that layout:

```bash
python3 kairos/data/make_legacy_set.py --n 60 --angles 90      # -> $IA3D_DATA/sets/shapenet_rr60
```

```
sets/shapenet_rr60/
  obj_meshes/<i>.obj       symlink to shapenet/<synset>/meshes/<id>.obj
  obj_meshes_90/<i>.obj    the same mesh, vertices rotated
  manifest.json            index -> synset, category, model id, source path
```

- **Selection:** deterministic round-robin over the synsets (sorted): round k takes the k-th id of every
  synset. With all 57 synsets, indices 1..57 are one mesh per category, so the meshes 1..25 used for
  training and mesh 40 (a mug) are all different categories. `--synsets 03001627,04379243` restricts the
  draw, which makes held-out indices unseen instances of seen categories instead.
- **Growing a set:** a larger `--n` or more `--angles` under the same `--name` extends the set without
  renumbering it. A different selection under an existing name is refused unless `--force` is given, which
  replaces the set and removes the mesh files of the old selection.
- **Rotation:** `x' = x cos a - z sin a`, `y' = y`, `z' = x sin a + z cos a`, the convention of
  `shift_objs.rotate_vertices_y`. In right-handed terms this is a rotation about +Y by `-a`: for 90 degrees
  `(x, y, z) -> (-z, y, x)`. Multiples of 90 degrees are written exactly.
- **Other angles:** `sdf.provider.SDFDataset` re-normalises every file by its own bounding box. That commutes
  with a rotation by a multiple of 90 degrees, but not with other angles: at 30 degrees the normalised
  rotated mesh differs from the rotated normalised mesh by up to 0.099 (airplane), because the bounding box
  changes. `check_set.py` reports this as a warning.

The scripts read `data/obj_meshes` by default. Either pass
`--data-root "$IA3D_DATA/sets/shapenet_rr60/obj_meshes"`, or link the set as `data` in a checkout
(`ln -s "$IA3D_DATA/sets/shapenet_rr60" data`; `/data` is in `.gitignore`).

Check a set (needs numpy and trimesh, so run it in the project environment; `pysdf` adds the SDF check):

```bash
kairos/in_env.sh python kairos/data/check_set.py "$IA3D_DATA/sets/shapenet_rr60"
```

It verifies that every mesh loads, is watertight and outward-oriented, lies inside the unit ball, that each
rotated file is exactly the rotated original, that the `SDFDataset` normalisation commutes with the rotation,
with `pysdf` that the SDF of the rotated mesh is the rotated SDF, and that the set holds no mesh file the
manifest does not list. It exits non-zero on any failure.

## Regenerating from raw ShapeNet

Only needed if the linked data is lost or a different subset is wanted.

```bash
# login node: download (skipped if the zip exists) and extract the first 200 models per synset
kairos/data/regen/download_shapenet.sh 200
# GPU node (CPU work, but the environment is aarch64): shells + SDF samples into $IA3D_DATA/shapenet/<synset>
kairos/sbatch.sh kairos/data/regen/preprocess_subset.sbatch all        # or "03001627 04379243"
python3 kairos/data/verify_shapenet.py
```

- The download needs `hf auth login` with an account that accepted the ShapeNet terms.
- `preprocess_subset.sbatch` skips a synset whose output directory is a symlink, and `preprocess_sdf.py`
  refuses to write through one, so the linked data cannot be overwritten. Remove the link of a synset (or
  set `IA3D_SHAPENET_OUT`) to regenerate it.
- `preprocess_subset.sbatch` ends with `PP_DONE` and exit code 0 only if every shape was processed.
  Otherwise it ends with `PP_FAILED` and the synsets to look at; submitting it again redoes only the shapes
  that are missing. The two models without geometry are skipped by name and do not count as failures.
- The tools need `libigl`, `scikit-image`, `scipy`, `trimesh` and `numpy`, all part of the project environment.
- In the original run a 200-model synset took about two minutes on 64 cores.
- The sampling seed of a model is 1000 plus its position in the sorted synset listing, so a full `--all`
  run reproduces the data. `regen/compare_regen.py <new> <reference>` compares two trees:

```bash
kairos/in_env.sh python kairos/data/regen/preprocess_sdf.py --all --limit 1 --workers 1 \
  --shapenet-dir "$IA3D_DATA/raw/ShapeNetCore.v1/extracted_200/ShapeNetCore.v1/02691156" \
  --out "$IA3D_DATA/regen_test/02691156"
kairos/in_env.sh python kairos/data/regen/compare_regen.py "$IA3D_DATA/regen_test/02691156" "$IA3D_DATA/shapenet/02691156"
```
